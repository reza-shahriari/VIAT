# Retire VIAT's Watcher, Keep an Auditor

VIAT can label video overnight with nobody watching, but no documented system labels video with nobody checking: Meta's SAM, SAM 2 and SAM 3 data engines, the best-documented cases of removing human effort at scale, all kept a human verification gate (a 500-image professional audit, a satisfactory/unsatisfactory check on every masklet, humans assigned to crowded scenes and tracking failures), so the realistic target is a person who works a short risk-ranked list of flagged tracks, reviews a few hundred random ones, and signs off on a certified error bound ([SAM paper](https://arxiv.org/html/2304.02643), [SAM 2 paper](https://arxiv.org/html/2408.00714v2), [SAM 3 paper](https://arxiv.org/html/2511.16719)). Both current workflows need a watcher for one structural reason: VIAT labels frames and single-object prompts, never objects with a life cycle, so it never gathers the cross-frame evidence that separates a car from its shadow, never decides that an object has entered or left, and never says where it is probably wrong; the auto-label worker's `'tracking'` strategy is a bare `pass`, and the SAM 3 path discards the object IDs and scores SAM 3 already computes and keeps only index 0 per frame ([main.py:198](../viat/main.py#L198), [sam3_native_manager.py:534](../viat/utils/sam3_native_manager.py#L534)). The missing layer is a well-measured recipe (detect every frame at a low threshold, give each track a tentative-to-confirmed-to-lost life cycle, extend each track backward from its first confident detection, repair tracks offline, rank tracks by risk) whose ingredients have published gains: SAM 3's temporal heuristics add **2.6–4.9 cgF1**, backward completion adds **5.3 AP**, learned verifiers add **8.3 cgF1** while doubling throughput, and verifying tracklets instead of drawing boxes cut workload by **up to 96%** ([SAM 3 paper](https://arxiv.org/abs/2511.16719), [SAM2BMP](https://iccvm.org/2026/files/papers/517.pdf), [Ince et al.](https://arxiv.org/abs/2101.06977)). The unsolved part is small-object recall in aerial footage, where native SAM 3 scores **25.6 HOTA** on a drone benchmark on which a detect-and-propagate pipeline reaches **55.4**, and text-only SAM 3 gets **11.7 mAP** on DIOR, so on VIAT's UAV video human corrections pay off most when fed back into the detector ([AeroTrack](https://arxiv.org/html/2607.08075), [arXiv 2607.09583](https://arxiv.org/html/2607.09583v1)). The build order is to stop discarding evidence first (IDs, scores, provenance, ID-preserving exports), then add a headless, resumable orchestrator whose tracker is built from permissively licensed parts, then offline repair, a risk-ranked review dock and an audit sampler, and only then verifiers, exemplar feedback and fine-tuning rounds. Licenses shape that stack: SAM 3's license bans military and ITAR-regulated uses, which matters for drone work, and VIAT's PyInstaller spec stops excluding AGPL-3.0 Ultralytics when built with AI support ([SAM 3 LICENSE](https://github.com/facebookresearch/sam3/blob/main/LICENSE), [viat.spec](../installation_tools/viat.spec#L31)).

## Both workflows need a watcher because VIAT labels frames, never objects

A person watching a VIAT run supplies three things the software never computes: evidence that builds up across frames, a decision that an object has started or stopped existing, and a judgment of where the output is probably wrong. Prompt → detect lacks the first and the third, prompt → track lacks the second and the third, and the data model lacks the structure (tracks, provenance, identities that survive export) that any automatic replacement would need.

### Prompt → detect trusts one frame and one score

Tools > Auto Label runs `AutoLabelWorker` as a genuine background QThread over the current frame or the whole video, but every frame is processed independently: the dialog always sends `'strategy': 'independent'`, and the branch that would handle `'tracking'` is empty ([auto_annotate_dialog.py:461](../viat/widgets/auto_annotate_dialog.py#L461), [main.py:198](../viat/main.py#L198)). A box missing on frame 212 but present on 211 and 213, a jittering box, or a class that flips between car and van therefore goes straight into the labels. The filters that exist are all per-frame (minimum score, ignore regions, a class-agnostic greedy NMS hard-coded at IoU 0.5, and deduplication against existing labels), and that fixed NMS both suppresses legitimately overlapping objects of different classes, such as a rider on a bicycle, and is the only defense against duplicates ([main.py:335](../viat/main.py#L335)). Class identity is fragile as well: detectors return the prompt string as `class_name`, and the prompt-to-class map `classes_info` is built but never read, so a class whose detection prompt differs from its name is saved under the prompt text and escapes its own per-class dedup rules ([main.py:223](../viat/main.py#L223), [main.py:9156](../viat/main.py#L9156)).

The only acceptance rule is one global minimum confidence (25% by default), and open-vocabulary scores cannot carry that weight because object size and prompt wording bias them. Grounding DINO gives small objects a mean confidence of **0.180 against 0.520** for large ones, and generic queries score 0.194 against 0.403 for specific ones, so any single high threshold silently deletes small objects ([arXiv 2607.10993](https://arxiv.org/html/2607.10993v1)). Two of VIAT's backends, Florence-2 and LocateAnything, return 1.0 for every detection and cannot be thresholded or ranked at all ([zero_shot_manager.py:414](../viat/utils/zero_shot_manager.py#L414), [zero_shot_manager.py:592](../viat/utils/zero_shot_manager.py#L592)), which mirrors multimodal-LLM detectors generally, since Qwen3-VL's authors set every confidence to 1.0 to compute mAP ([Qwen3-VL report](https://arxiv.org/pdf/2511.21631)). VIAT's own UAV footage shows why a threshold cannot remove false positives: when the shadow filter was calibrated, shadows mis-detected as objects scored **0.3–0.55**, squarely inside the band a recall-oriented threshold must admit ([shadow_filter.py:11](../viat/utils/shadow_filter.py#L11)).

Aerial imagery with a large vocabulary is the worst case for every current model. On the LAE-80C aerial benchmark the best open-vocabulary detector, OWLv2, reached an F1 of only **27.6%** while producing **47,058 false positives against 21,408 true positives**; cutting the prompt vocabulary from 80 classes to about 3.2 per image improved results **15×**, and the authors identify confusion between class names, not visual feature extraction, as the bottleneck ([arXiv 2601.22164](https://arxiv.org/html/2601.22164v1)). SAM 3 prompted with text alone scores 11.67 mAP on DIOR, and cast shadows cost it 2–4 mAP on vehicles ([arXiv 2607.09583](https://arxiv.org/html/2607.09583v1)). Nothing in VIAT's auto-label path checks a detection with an independent model: the CLIP/SigLIP refiner only sets an `uncertain` flag, runs on the GUI thread, reads pixels only for image datasets, and cannot load in the current environment because `transformers` is not installed ([zero_shot_classifier.py:278](../viat/utils/zero_shot_classifier.py#L278), [main.py:5830](../viat/main.py#L5830)). Every error the user fixes by hand (false positives, misses, wrong classes, duplicates, loose boxes) is invisible to the software, so the human eye is the only error detector.

### Prompt → track follows one object and cannot tell when it has failed

The SAM Interactive dock sends one prompt, one class and a frame range to `on_sam_track_requested`, which writes exactly one box per frame, `tracked_boxes[0]`, with `source='sam_tracked'`, no track ID and the default score of 1.0 ([main.py:3052](../viat/main.py#L3052), [annotation.py:148](../viat/annotation.py#L148)). With a text prompt SAM 3 does track several instances, but `_outputs_to_frame_result` drops `out_obj_ids` and `out_probs`, so index 0 can be a different physical object on different frames and VIAT manufactures ID switches inside what looks like a single track ([sam3_native_manager.py:534](../viat/utils/sam3_native_manager.py#L534)). Discovery also stops early: tracking runs in 400-frame chunks, and between chunks the session is cleared and re-prompted with only the last box, so after frame 400 a text-prompted run becomes a single box-prompted track ([main.py:3105](../viat/main.py#L3105)). The SAM 3.1 path additionally inherits the builder's default cap of **16 tracked objects**, because VIAT calls `build_sam3_predictor` without `max_num_objects` ([sam3_native_manager.py:224](../viat/utils/sam3_native_manager.py#L224), [model_builder.py](https://github.com/facebookresearch/sam3/blob/main/sam3/model_builder.py)), and above the cap new arrivals are dropped with nothing more than a log warning ([sam3_video_base.py](https://github.com/facebookresearch/sam3/blob/main/sam3/model/sam3_video_base.py)).

Nothing handles the life cycle the watcher manages by hand. Objects that enter after the prompt frame are never picked up by an existing job, objects that leave produce empty frames under SAM or a hard stop with "Tracking lost." under the fast single-object trackers ([fast_tracker_manager.py:97](../viat/utils/fast_tracker_manager.py#L97)), and nothing re-identifies an object that returns. Drift is undetectable because every tracked box claims full confidence, and the obvious substitute is weak: SAM 2's predicted-IoU head tells whether a frame's true IoU exceeds 0.5 with a peak accuracy of only **about 0.74** on the VOST benchmark, with a best threshold near 0.8 rather than 0.5 ([LIT paper](https://arxiv.org/html/2603.26929v1)). The tracking-mode toggle that re-derives IDs afterwards draws them from a pool bounded by each class's per-frame count, so two different objects can share a `track_id` over time ([main.py:11472](../viat/main.py#L11472)). Long videos add memory failures that upstream has not fixed: SAM 3's inference state grows with every propagated frame ([sam3#169](https://github.com/facebookresearch/sam3/issues/169)), and users who chunk videos to fit consumer GPUs report losing objects at chunk transitions ([sam3#354](https://github.com/facebookresearch/sam3/issues/354)), the same pattern as VIAT's 400-frame chunks.

Even the Track Queue, VIAT's most unattended feature, is built for one-prompt-one-object jobs and runs on the GUI thread with `processEvents`; its statuses are saved only when the user clicks Save Queue, and `viat/run.py` has no command-line mode ([main.py:3748](../viat/main.py#L3748), [main.py:3471](../viat/main.py#L3471), [run.py](../viat/run.py)). Unattended, today, means leaving the application open and hoping nothing needs a click.

### The missing layer is a track with provenance and a reason to look

Per-box review fields already exist, since `BoundingBox` carries `score`, `source`, `original_source`, `verified` and `uncertain`, all saved in the project JSON ([annotation.py:143](../viat/annotation.py#L143)). What is missing sits above the box. There is no track object, and identity lives only in `attributes['track_id']` or `actor_id`. Provenance is inconsistent: zero-shot boxes from the Class Frames and Empty Frames docks are saved with source `'manual'`, which marks them `verified=True` and drops the model's score ([main.py:2012](../viat/main.py#L2012)), and an audit cannot certify machine labels it cannot tell apart from human ones. Exports then erase what identity exists. The per-video Raya TXT writer stores no track ID, score, source or verification flag ([file_operations.py:786](../viat/utils/file_operations.py#L786)); the VIAT JSON exporter drops score and source and, when boxes lack an `actor_id`, falls back to per-frame actor keys that can overwrite each other, which is inferred from the code rather than tested ([viat_json.py:231](../viat/utils/label_formats/viat_json.py#L231)); and the evaluation engine's MOT converter substitutes per-frame box indices for missing IDs, which makes the association half of HOTA meaningless on today's exports ([convert_ourformat2mot.py:247](../viat/evaluation/utils/convert_ourformat2mot.py#L247)). Without IDs and scores nothing downstream can rank, and without ranking a human must look at everything. The table maps each manual task to its cause.

| Manual task today | Why the software cannot do it | Where in VIAT | Automatic replacement |
|---|---|---|---|
| Placing prompts | Discovery exists only as a user prompt; the auto-label `'tracking'` path is empty | [main.py:198](../viat/main.py#L198) | Detector-driven births on every frame |

## Research has solved life cycles and verification; aerial recall is still open

Every task in that table has at least one published answer with numbers, and the answers converge on a few mechanisms. The summary comes first; the detail after it explains which answers transfer to VIAT and where the evidence stops.

### Detector-driven life cycles replace prompt placing and exit handling

SAM 3's video mode is the most complete reference because its code, not just its paper, specifies the rules. A concept detector runs on every frame while existing masklets are propagated, detections and masklets are matched by mask IoU, and a detection starts a new object only if its score is at least **0.7 (0.65 in SAM 3.1)** and it overlaps no existing track by even 0.1 IoU. Outputs are held back 15 frames so that a new masklet unmatched on 8 of its first 15 frames, or sharing a detection with an older masklet for 8 frames, is deleted before it is ever shown, and every 16 frames the tracker is re-seeded from unambiguous detections whose score and IoU both reach 0.8 ([sam3_video_base.py](https://github.com/facebookresearch/sam3/blob/main/sam3/model/sam3_video_base.py), [model_builder.py](https://github.com/facebookresearch/sam3/blob/main/sam3/model_builder.py)). Turning these temporal heuristics off costs **2.6–4.9 cgF1**, and the full system reaches over 80% of human pHOTA ([SAM 3 paper](https://arxiv.org/abs/2511.16719), [SAM 3 paper HTML](https://arxiv.org/html/2511.16719)).

Its weaknesses line up with VIAT's footage. Masklets are hidden but never retired, so memory and compute grow with every object ever seen; long videos run out of memory ([sam3#169](https://github.com/facebookresearch/sam3/issues/169)); the detector cannot be swapped for a fine-tuned YOLO; and on a stress video with more than 80 vehicles on a 24 GB card, native SAM 3 finished only with a budget of **7 or fewer objects** ([AeroTrack](https://arxiv.org/html/2607.08075)). On the AeroVIS drone benchmark it scored **25.6 HOTA with a detection accuracy (DetA) of 12.3 but an association accuracy (AssA) of 56.8**, which means it links what it finds acceptably and misses most small objects ([AeroTrack](https://arxiv.org/html/2607.08075)).

Detector-prompted SAM 2 trackers keep this structure but make the detector pluggable. SAM2MOT starts a track when more than half of a high-confidence detection's box lies outside all tracked masks, bins SAM 2's object logits into reliable, pending, suspicious and lost states at 8, 6 and 2, re-prompts pending tracks from matched detections, and deletes after 25 lost frames; with the same detector it beats ByteTrack by **75.8 to 53.3 HOTA** on DanceTrack and by 74.4 to 67.8 IDF1 on UAVDT, with 141 instead of 452 ID switches ([SAM2MOT](https://arxiv.org/html/2504.04519v2), [SAM2MOT v5](https://arxiv.org/abs/2504.04519)). LiAM-SAM adds contrastive birth checks and motion-grounded memory correction and cuts DanceTrack ID switches from **36,210 to 1,416**, but runs at 2 FPS with 30 objects on an A100 ([LiAM-SAM](https://arxiv.org/abs/2609.28078)).

AeroTrack, the one drone-specific design, runs an open-vocabulary detector every 25 frames, propagates with SAM 2 or SAM 3 inside segments whose memory is reset at each boundary, and revives lost tracks with a gated score of 0.45·IoU + 0.30·centre similarity + 0.25·area consistency; it reaches **55.4–55.8 HOTA on AeroVIS against 25.6 for native SAM 3 and 35.0 for DEVA** ([AeroTrack](https://arxiv.org/html/2607.08075)). None of the three has released code, so VIAT must reimplement from the papers, but they converge on one design: births gated by high confidence and low overlap, track states taken from the tracker's own confidence, re-prompting from confident detections, deletion after 5–30 weak frames, and bounded memory, where Seg2Track's 16-frame window cut memory by up to 75% with negligible loss ([Seg2Track-SAM2](https://arxiv.org/html/2509.11772v2)).

Box-only tracking-by-detection is the cheap end of the spectrum: its cost is negligible next to the detector, and its whole life cycle is five numbers, which in Ultralytics' defaults are a high threshold of 0.25, a low threshold of 0.1, a new-track threshold of 0.25, a 30-frame buffer and a match threshold of 0.8 ([botsort.yaml](https://github.com/ultralytics/ultralytics/blob/main/ultralytics/cfg/trackers/botsort.yaml)). Its identity quality on drone footage is poor out of the box, with YOLO plus ByteTrack at about 38.5 HOTA on VisDrone-MOT validation in an abstract-level report ([OATrack](https://doi.org/10.3390/s26165222)), but motion engineering helps: flow-guided FOLT lifts VisDrone IDF1 from 37.0 (ByteTrack) to 56.9 ([FOLT](https://arxiv.org/abs/2308.07207)), and camera-motion compensation alone adds 1.62 IDF1 on MOT17 ([BoT-SORT](https://arxiv.org/abs/2206.14651)).

No annotation product ships the whole loop. Commercial SAM-based video tracking is seeded by a user and bounded: Encord tracks 30 frames by default ([Encord docs](https://docs.encord.com/platform-documentation/Annotate/automated-labeling/annotate-sam)) and Kili 50 ([Kili changelog](https://docs.kili-technology.com/changelog/november-6th-2024)), CVAT's tracking functions by design "cannot discover new objects" ([CVAT SDK docs](https://docs.cvat.ai/docs/api_sdk/sdk/auto-annotation/)) and its SAM 3 support is image-only ([CVAT SAM 3 changelog](https://www.cvat.ai/resources/changelog/sam3-text-prompts)), and Label Studio's SAM 2 video backend tracks one object ([Label Studio SAM 2 backend](https://github.com/HumanSignal/label-studio-ml-backend/tree/master/label_studio_ml/examples/segment_anything_2_video)). X-AnyLabeling, the closest desktop analogue and GPL-3.0, runs SAM 3 video for one text category per session and loses all results if propagation is cancelled ([X-AnyLabeling SAM 3 README](https://github.com/CVHub520/X-AnyLabeling/blob/main/examples/interactive_video_object_segmentation/sam3/README.md)). Only Encord documents track-level QA metrics, namely broken tracks, inconsistent tracks that signal ID switches, and inconsistent classes ([Encord metrics](https://docs.encord.com/platform-documentation/Annotate/active-annotate/basics/annotate-video-metrics-label-validation)), and Voxel51's confidence-prioritized verification is an Enterprise-only beta ([FiftyOne VAL](https://docs.voxel51.com/enterprise/verified_auto_labeling.html)). VIAT would be combining pieces nobody sells together.

### Offline look-ahead repairs what online trackers break

VIAT never needs real-time output, and the auto-labelers that reached human quality exploited exactly that freedom. Tesla auto-labeled 10,000 clips in about a week, work it estimated at several months by hand ([WRAL/CNN](https://www.wral.com/archive/20353852/)), using offline networks that see future frames ([TDS AI Day review](https://towardsdatascience.com/tesla-ai-day-2021-review-part-2-training-data-how-does-a-car-learn-e8863ba3f5b0/)). Waymo's offboard 3DAL came within about 1 AP of human labelers, and a student trained on 10% human plus 90% auto labels nearly matched full human supervision (70.0 vs 71.2) ([3DAL](https://arxiv.org/abs/2103.05073)); its successor DetZero exceeded human labelers at **90.24 vs 86.45** 3D AP@0.7 ([DetZero](https://arxiv.org/abs/2306.06023)). In 2D video the same idea is backward completion: SAM2BMP propagates each track backward from its first detection because small or partly occluded objects rarely produce confident detections when they first appear, and that was its single largest gain, **+5.3 AP** on YouTube-VIS 2021, followed by +2.7 AP from dropping tracks whose detector support covers under 10% of their length ([SAM2BMP](https://iccvm.org/2026/files/papers/517.pdf)). CTRL's bidirectional extension cut totally missed vehicles on Waymo from 21.4k to 5.1k ([CTRL](https://arxiv.org/abs/2304.12315)).

Offline track repair is cheap and additive. Linear interpolation over gaps of up to 20 frames raised ByteTrack's MOT17 validation MOTA from 76.6 to 78.3 ([ByteTrack](https://arxiv.org/abs/2110.06864)); StrongSORT's appearance-free link model plus Gaussian-smoothed interpolation added 0.9–3.8 IDF1 across five trackers at 1.7 and 7.1 ms per frame ([StrongSORT](https://arxiv.org/abs/2202.13514)); appearance-based split-and-connect (GTA) added 3.7–10.2 HOTA on sports footage ([GTA](https://arxiv.org/abs/2411.08216)); and video-level class suppression and sequence rescoring added 2.2–3.8 and 6.5 mAP on ImageNet VID ([T-CNN](https://arxiv.org/abs/1604.02532), [Seq-NMS](https://arxiv.org/abs/1602.08465)). The caveat for drones is appearance: VisDrone objects are small and look alike, and FOLT's authors conclude that "appearance-matching strategy is not important in UAV-MOT scenes" ([FOLT](https://arxiv.org/abs/2308.07207)), so linking must lean on motion in camera-stabilized coordinates. Shot boundaries come first; TransNet V2 reaches F1 96.2 on BBC footage, while PySceneDetect's AdaptiveDetector, which VIAT already uses, reaches 91.6 there but only about 56 on ClipShots' hard cuts ([TransNet V2](https://arxiv.org/abs/2008.04838), [PySceneDetect benchmarks](https://www.scenedetect.com/benchmarks/)).

Detecting failure without ground truth is the weakest link. The only signal with published precision and recall is the classic forward–backward check, with 95% recall and 96% precision on point trajectories at a 1-pixel threshold ([Kalal et al.](http://kahlan.eps.surrey.ac.uk/featurespace/tld/Publications/2010_icpr.pdf)). Working systems therefore stack weaker signals: SAM 3's masklet detection score requires a track to match a detection in at least half of a 15-frame window ([SAM 3 paper](https://arxiv.org/abs/2511.16719)); DAM4SAM's memory gate trusts a frame only when predicted IoU exceeds 0.8 and the mask area stays within 20% of its 10-frame median ([DAM4SAM](https://arxiv.org/html/2411.17576)); AWS's QA recipe flags consecutive-box IoU below 0.5, size changes above 20% and crop-embedding jumps beyond 2σ ([AWS blog](https://aws.amazon.com/blogs/machine-learning/quality-assessment-for-sagemaker-ground-truth-video-multi-frame-object-tracking-annotations-using-statistical-analysis/)); and Uber's production validator is an XGBoost model over 11-frame windows with 283 motion, appearance and coordinate features ([Uber blog](https://www.uber.com/us/en/blog/validating-bounding-box/)). Neither AWS nor Uber has published how well its flags work.

### Exemplars, tiling and a second opinion shrink detector errors

Visual exemplars are the largest single-step accuracy lever measured. One exemplar box lifts SAM 3's COCO AP on images containing the object from 58.8 (text only) to **78.1** (text plus exemplar), and three interactive exemplar clicks add 21.6 cgF1 over text alone before plateauing around four ([SAM 3 paper](https://arxiv.org/abs/2511.16719)); on aerial data, one box exemplar takes SAM 3 on DIOR from **11.67 to 63.79 mAP** ([arXiv 2607.09583](https://arxiv.org/html/2607.09583v1)). SAM 3's exemplars are per-image, though, so reusing a correction across frames or images requires YOLOE's `refer_image`, a prototype memory bank (training-free DINOv2 banks reach 36.8 nAP on COCO few-shot detection), or fine-tuning ([Ultralytics discussion #23968](https://github.com/orgs/ultralytics/discussions/23968), [No time to train!](https://arxiv.org/abs/2507.02798)). Fine-tuning on ten examples per class roughly doubles out-of-domain accuracy, taking SAM 3 from 15.2 to 36.5 AP and Grounding DINO from 15.7 to about 33 on RF100-VL ([SAM 3 paper](https://arxiv.org/abs/2511.16719), [RF100-VL](https://arxiv.org/html/2505.20612)).

Slicing-aided inference adds 5.1–6.8 AP on VisDrone without retraining and 12.7–14.5 AP with slice-aware fine-tuning ([SAHI](https://arxiv.org/abs/2202.06934)). Ensembles help only across genuinely different models: weighted boxes fusion adds 1.3 mAP over the better of two EfficientDets but degrades a single model's output ([WBF paper](https://arxiv.org/abs/1910.13302)). Thresholds should favor recall; in Voxel51's study of YOLO-World, YOLOE and Grounding DINO labels, auto-label F1 peaked at an average threshold of 0.33, the best training labels came from **0.2**, and a 0.8 threshold gave the worst downstream model in every experiment ([Voxel51 paper](https://arxiv.org/abs/2506.02359)). Hard negatives matter as much as positives, since training SAM 3 with 30 hard-negative phrases per image raised cgF1 from 28.3 to 43.0 ([SAM 3 paper](https://arxiv.org/html/2511.16719)).

A second model catches what thresholds cannot. SAM 3's data engine fine-tuned Llama 3.2 on about 10 million human accept/reject decisions to build a mask verifier (77.7% accuracy against 75.0% for a single human) and an exhaustivity verifier (81.1% against 81.8%); applied to SAM 3's own outputs they add **8.3 cgF1** (54.0 → 62.3), and they roughly doubled engine throughput with a 5× speed-up on concepts absent from the image ([SAM 3 paper](https://arxiv.org/abs/2511.16719)). Those verifier weights do not appear to be public. Zero-shot vision-language judges are weaker but real: GPT-4o review of Grounding DINO labels raised a downstream YOLOv8n from 0.771 to 0.802 AP ([DART](https://arxiv.org/html/2407.09174)), Gemini 2.5 Flash as a judge lifted industrial-diagram detection from 0.728 to 0.925 mAP while failing where symbols were densely packed ([arXiv 2510.03376](https://arxiv.org/html/2510.03376)), and a local 7B VLM serves 13–21 requests per second on one A100 ([vLLM #24728](https://github.com/vllm-project/vllm/issues/24728)), which makes per-track verification affordable offline.

For ranking likely label errors, ObjectLab's precision among its top 100 flagged COCO images was 0.58 against 0.22 for per-image mAP scoring ([ObjectLab](https://dmlr.ai/assets/accepted-papers/112/CameraReady/objectlab_icml2023_lowerres.pdf)), and loss inspection found real errors in 71.5% of its top-200 VOC suspects ([loss inspection](https://arxiv.org/html/2303.06999)), yet the best detectors of label errors still miss up to 66% of them, missing boxes most of all ([REC✓D](https://arxiv.org/html/2508.06556)).

### Every documented data engine kept a human verification gate

Meta's three engines are the best-documented cases of removing human effort at scale, and all kept people in the loop. SAM's time per mask fell from 34 to 14 seconds and 99.1% of SA-1B's masks were generated automatically, but a 500-image professional audit still certified them, finding 94% within IoU 0.9 of the corrected version ([SAM paper](https://arxiv.org/html/2304.02643)); SAM 2's propagate-then-correct loop cut video annotation from 37.8 to **4.5 seconds per frame**, yet every masklet still passed a human satisfactory/unsatisfactory check ([SAM 2 paper](https://arxiv.org/html/2408.00714v2)); and SAM 3's video phase concentrated humans on clips with crowded objects and tracking failures ([SAM 3 paper](https://arxiv.org/html/2511.16719)).

The measured wins come from changing the human's task from drawing to deciding. A yes/no box verification takes **1.6 seconds** against 26–42 seconds to draw a box ([Papadopoulos et al.](https://ar5iv.labs.arxiv.org/html/1602.08405)); SPAM asked humans only about uncertain tracklet decisions, putting them on just 3.3% of objects in MOT17 (10% in MOT20, 20% in DanceTrack), and ByteTrack trained on the result matched ground-truth training at 51.6 vs 50.6 HOTA ([SPAM](https://arxiv.org/html/2404.11426)); and verifying tracklets built from low-threshold detections cut annotation workload by **up to 96%** on the Multidrone dataset ([Ince et al.](https://arxiv.org/abs/2101.06977)). One result warns against the obvious review interface: in SAM 3's video engine, annotators who started from pre-made masklets were **40% slower** than those who started from the noun phrase (3,221 vs 2,307 seconds per video-phrase pair) ([SAM 3 paper](https://arxiv.org/pdf/2511.16719)). Correcting a machine track frame by frame can be slower than starting over, so the review task has to be a decision with one-click remedies.

How good labels must be depends on their use. Detectors tolerate missing boxes, since dropping 30% of VOC boxes cost about 5% mAP ([Soft Sampling](https://arxiv.org/abs/1806.06986v1)) and tiny aerial objects lost under 2 mAP from missing or extra labels even at 60% noise, but in the same aerial study class shifts hurt badly and box noise nearly halved tiny-object mAP ([arXiv 2401.08056](https://arxiv.org/html/2401.08056)). Detectors trained purely on zero-shot auto-labels reach 93–95% of human-label mAP50 on VOC and COCO but only 62–68% on BDD100K and LVIS ([Voxel51 paper](https://arxiv.org/abs/2506.02359)), the domain-shifted, small-object regime that drone footage belongs to. Statistical guarantee methods exist, but none has been validated on boxes or tracks: threshold-based auto-labeling needs on the order of 1/ε² validation labels and, on a 200-class task, auto-labeled only 32.2% of the data at 9% error from 10,000 of them ([TBAL](https://arxiv.org/pdf/2211.12620)); conformal labeling auto-labeled 65% of ImageNet at a controlled 10% false-discovery rate ([Conformal Labeling](https://arxiv.org/html/2510.14581)); and exact binomial bounds say that 299 randomly sampled items with no errors certify an error rate at or below 1% with 95% confidence ([binomial CI](https://en.wikipedia.org/wiki/Binomial_proportion_confidence_interval)).

### What nobody has solved

Five gaps shape the plan. Open-vocabulary recall on small aerial objects is poor for every model (11.67 mAP text-only on DIOR, F1 under 28% on LAE-80C, a detection accuracy of 12.3 for native SAM 3 on AeroVIS), and no VisDrone box AP has been published for SAM 3, SAM 3.1 or YOLOE-26. No ground-truth-free estimator of track quality has validated error bars, so every drift or ID-switch signal is a ranking heuristic until audited decisions calibrate it. No study measures human correction time for detect-and-track pipelines, for which HOTA and cgF1 are only proxies. The best designs (SAM2MOT, AeroTrack, LiAM-SAM) have no released code, and SAM 3's verifiers have no released weights. And SAM 3 still runs out of memory on long or dense videos, including SAM 3.1 on a 24 GB card ([sam3#511](https://github.com/facebookresearch/sam3/issues/511)). The consequences for VIAT follow directly: it must measure itself on its own footage, keep the detector swappable and fine-tunable, and treat any risk score as a ranking until its own audits calibrate it.

## An overnight run: detect low, track with a life cycle, repair offline, score every track

The design follows five rules drawn from the evidence. It runs offline and uses look-ahead everywhere, because nothing is lost by waiting and backward passes are free. It separates a low candidate threshold that protects recall from an acceptance decision that protects precision. It makes the track, not the frame, the unit of evidence and of review. It stamps every box with provenance and every flagged track with a reason. And it runs headless, resumes after a crash, skips missing optional backends through VIAT's `try/except ImportError` convention, and fails loudly rather than silently: health checks fire when detections or tracks drop to zero, because integrations do fail silently, as when Ultralytics' SAM 3 video predictor loses every track with an incompatible checkpoint ([ultralytics#25152](https://github.com/ultralytics/ultralytics/issues/25152)), and state lives on disk because CVAT's tracking agent loses its state when it crashes ([CVAT SAM 2 tracker docs](https://docs.cvat.ai/docs/annotation/auto-annotation/segment-anything-2-tracker/)). The whole run fits in one loop:

```text
autorun(job):                                   # job = Track Queue "auto" job (JSON), resumable
  for video in job.videos:
    cuts, gmc = preflight(video)                # PySceneDetect / TransNet V2; per-frame affine + inlier count
    for shot in split(video, cuts):             # no track crosses a cut
      for t in shot.frames:
        dets = detect(t) if (t % K == 0 or trigger(t)) else []
               # candidates at 0.2 (SAM 3: 0.5); per-model class-aware NMS; WBF across models;
               # tiles for small objects; SAM box->mask for tight boxes and a looseness feature
        preds = propagate(active_tracks, t)     # Mode A: SAM 3 | B1: SAM 2.1 / SAM2-TRT segment | B2: Kalman + CMC
        match dets to preds                     # IoU and IoM matrices, one-to-one assignment
        for det not explained (IoU and IoM < 0.1 to all tracks) with score >= 0.65 and > 50% uncovered:
            revive best lost-bank track if its gated score passes, else spawn a tentative track
        update keep-alive, consecutive-detection, unmatched-run, duplicate-overlap, class-vote counters
        confirm after 3 matched detections; re-seed every 16 frames from 1:1 dets (score, IoU >= 0.8)
        re-seed now if a matched box drifts below IoU 0.85; hide the newer-occluded of pairs at mask IoU >= 0.7
        lost when keep-alive <= -4; retire after 25-30 lost frames; reset tracker memory every 16-25 frames
        checkpoint every N frames; health-check detection and track counts
    offline, per track:
      hotstart filter: delete if >= 8 of first 15 frames unmatched, or a duplicate of an older track >= 8 frames
      extend backward from first / forward from last confirmed frame (<= 40 frames, with stop rules)
      split impure -> link fragments -> drop support < 10% -> tracklet NMS -> fill gaps <= 20
        -> smooth -> class vote -> shadow check; append every step to the repair log
      verify K sampled crops (embedding-bank margin; optional VLM two-view check)
      risk = f(support, tracker bands, geometry jumps, overlap, class margin, verifier, repairs, context)
      route: auto-reject -> hard-negative bank | review queue (risk x frames) | auto-accept
  write project JSON + tracks table, exports that keep IDs, run report, audit sample
```

### Pre-flight and detection set the recall ceiling

Every video first gets shot boundaries from VIAT's existing PySceneDetect AdaptiveDetector wrapper, with TransNet V2 as an optional upgrade for edited footage, and no track or propagation may cross a cut ([scene_splitter.py:76](../viat/utils/scene_splitter.py#L76)). A per-frame affine camera-motion estimate from sparse optical flow is stored with its inlier count so that every motion test runs in stabilized coordinates, and frames with few inliers are marked unreliable, because camera-motion estimation fails when moving objects crowd out background keypoints ([BoT-SORT](https://arxiv.org/abs/2206.14651)).

Detection then runs on every frame (K = 1) for small or dense objects and every 5–25 frames for footage with a few large objects, with extra runs triggered by uncertain tracks, cuts and new activity at the frame border. Candidates are kept at 0.2 for YOLO-family and Grounding DINO detectors and at 0.5 for SAM 3's calibrated detector ([Voxel51 paper](https://arxiv.org/abs/2506.02359), [SAM 3 paper](https://arxiv.org/html/2511.16719v1)). The vocabulary is restricted per video to the classes that plausibly occur, NMS runs per model and per class, weighted boxes fusion (WBF) merges across models, and overlapping tiles recover small objects ([SAHI](https://arxiv.org/abs/2202.06934)). SAM then refines detector boxes into masks, so boxes are tight and the IoU between the detector's box and the mask's box becomes a looseness feature. Florence-2 and LocateAnything, which emit constant scores, can vote as second opinions but never create tracks or accept labels. One convention needs an explicit decision: boxes derived from masks cover only the visible part of an occluded object, so if VIAT's guideline is amodal the detector's box should be kept wherever one exists ([SAM2MOT](https://arxiv.org/html/2504.04519v2)).

### A life-cycle tracker turns detections into objects

Each track moves through tentative, confirmed, lost and retired states, and SAM 3's code-verified rules supply the defaults. A detection counts as explained if it overlaps any track with an IoU or intersection-over-minimum (IoM) of 0.1; an unexplained detection starts a tentative track only if its score is at least 0.65–0.7 and more than half of its area lies outside existing tracks; and a tentative track is confirmed after 3 consecutive matched detections ([model_builder.py](https://github.com/facebookresearch/sam3/blob/main/sam3/model_builder.py), [SAM2MOT](https://arxiv.org/html/2504.04519v2)). Before a new ID is issued, the candidate is compared against a bank of recently lost tracks using AeroTrack's gated geometric score, plus an appearance embedding only where objects are large enough for appearance to mean anything ([AeroTrack](https://arxiv.org/html/2607.08075)).

Confirmed tracks are re-seeded every 16 frames from unambiguous detections whose score and IoU are both at least 0.8, and immediately when a matched detection's box drifts below 0.85 IoU with the tracked box, a trigger the SAM 3 paper describes and the shipped SAM 3.1 code leaves off. When two tracks' masks overlap by 0.7 or more, the more recently occluded one is hidden; after about 8 unmatched frames a track is lost, and after 25–30 lost frames at 30 fps it is retired and its memory freed ([sam3_video_base.py](https://github.com/facebookresearch/sam3/blob/main/sam3/model/sam3_video_base.py), [SAM 3 paper](https://arxiv.org/abs/2511.16719), [SAM2MOT](https://arxiv.org/html/2504.04519v2)). Tracker memory is reset and re-seeded from current masks every 16–25 frames to keep VRAM flat on long videos ([Seg2Track-SAM2](https://arxiv.org/html/2509.11772v2), [AeroTrack](https://arxiv.org/html/2607.08075)). Because the run is offline, SAM 3's hotstart rules become simple filters on finished tracks (delete any track unmatched on 8 of its first 15 frames or duplicating an older track for 8 frames), so the forward pass can afford a lenient birth threshold; with box-only MOT these filters cost nothing, while with mask propagation a spurious tentative track costs compute until it is deleted.

### Back-fill, repair and risk scoring finish each track

After the forward pass, each confirmed track that begins partway through its shot is propagated backward from its first confirmed detection for up to 40 frames, stopping earlier if the tracker's confidence drops, the mask vanishes, the track overlaps another by 0.7, or a cut intervenes; the same step runs forward from its last confirmed frame ([Grounded-SAM-2 "plus" script](https://github.com/IDEA-Research/Grounded-SAM-2/blob/main/grounded_sam2_tracking_demo_with_continuous_id_plus.py), [SAM2BMP](https://iccvm.org/2026/files/papers/517.pdf)). Filled boxes get their own `source` value and a lower training weight.

Repair then runs in a fixed order: split tracks whose appearance clusters into distinct identities; link fragments whose gap, stabilized motion and size agree; drop tracks whose detector support covers less than 10% of their length and suppress duplicate tracklets overlapping above 0.5 IoU for 6 or more frames; interpolate gaps of up to 20 frames and smooth trajectories; give each track the confidence-weighted majority class of its detections; and rerun the shadow check on low-score births ([SAM2BMP](https://iccvm.org/2026/files/papers/517.pdf), [StrongSORT](https://arxiv.org/abs/2202.13514), [GTA](https://arxiv.org/abs/2411.08216)). Every operation goes into a per-track repair log, because a track that needed three merges and ended with a 55% class vote is exactly the track a human should see.

The risk score combines signals that each have a published use: detector support and the longest unsupported run (SAM 3's masklet detection score), tracker-confidence bands (SAM2MOT's logit states), area and size jumps against a running median (DAM4SAM and AWS), velocity outliers in stabilized coordinates, maximum overlap with another track, appearance that splits into several clusters within one track, class-vote margin and cross-model disagreement, verifier margin, repair-log counts, and context such as crowding, tiny size or an unreliable camera-motion estimate ([SAM 3 paper](https://arxiv.org/abs/2511.16719), [SAM2MOT](https://arxiv.org/html/2504.04519v2), [DAM4SAM](https://arxiv.org/html/2411.17576), [AWS blog](https://aws.amazon.com/blogs/machine-learning/quality-assessment-for-sagemaker-ground-truth-video-multi-frame-object-tracking-annotations-using-statistical-analysis/), [GTA](https://arxiv.org/abs/2411.08216)). At first the score is a hand-weighted sum with hard flags; once reviewers have logged a few thousand decisions it becomes a gradient-boosted classifier in the style of Uber's validator, calibrated against the random audit ([Uber blog](https://www.uber.com/us/en/blog/validating-bounding-box/)).

Each track is then routed to one of three places: auto-reject into a hard-negative bank (tentative tracks that never confirmed, and unsupported or duplicate tracks), the review queue (ranked by risk multiplied by the number of frames the track affects), or auto-accept (everything else, subject to the audit). For image folders the temporal stages drop out and ranking relies on cross-model disagreement, verifier margin and ObjectLab-style scores computed with an independent model, because a checker that shares the labeler's systematic errors cannot see them ([ObjectLab](https://dmlr.ai/assets/accepted-papers/112/CameraReady/objectlab_icml2023_lowerres.pdf)).

The compute arithmetic favors detecting every frame with a YOLO-class detector: YOLO-World labeled VOC's 16,551 training images in 197 seconds on an L40S, about 84 images per second ([Voxel51 paper](https://arxiv.org/html/2506.02359)), so by our arithmetic a three-minute 30 fps clip (5,400 frames) takes about a minute, or about four with 2×2 tiling. Mask propagation is the expensive part and scales with object count: SAM 3 is near real time only for about five concurrent objects on an H200, SAM 3.1's multiplexing is reported to double throughput for medium object counts (16 to 32 FPS on an H100), and LiAM-SAM falls to 2 FPS at 30 objects ([SAM 3 paper](https://arxiv.org/html/2511.16719), [Meta AI blog](https://ai.meta.com/blog/segment-anything-model-3/), [LiAM-SAM](https://arxiv.org/abs/2609.28078)). No VRAM figures are published for SAM 3 or 3.1, so the mode for dense scenes should follow a benchmark on VIAT's own RTX 5090 and RTX A6000. With two GPUs the detector and the propagator belong on different cards, which requires setting `CUDA_DEVICE_ORDER=PCI_BUS_ID`: today `nvidia-smi` and torch enumerate the two cards in opposite orders, and `gpu_env.restrict_to_saved_gpu()` pins each process to one index ([gpu_env.py](../viat/gpu_env.py)).

The order follows dependencies and payoff. It also already turns Mode A into multi-object discovery for sparse scenes in the GUI. Phase 1 removes the watching, and Mode B2 comes first within it because it is cheap, permissive and detector-agnostic, and suits dense drone scenes where propagating every object through SAM is slowest. Phase 2 removes frame-by-frame review. Phase 3 attacks the one problem research has not solved, small-object recall, where a human correction turned into an exemplar is worth most. Phase 4 compounds the logs everything before it collects, which is also why decision logging ships in Phase 2 rather than Phase 4.

## The human's job shrinks to ranked exceptions plus a 300-track audit

### One decision per flagged track replaces frame-by-frame repair

The morning after a run, the reviewer opens a Review Queue dock that lists flagged tracks across all videos, sorted by risk times affected frames, each with reason codes such as "unsupported by any detection for 42 frames", "area jumped 35% at frame 1,810", "class vote 55% car / 45% van" or "revived from the lost bank after 60 frames". Selecting one shows a strip of crops sampled at 1–2 frames per second along the track with the risky frames highlighted, and the reviewer answers with one key: accept; reject, which also files the crops in the hard-negative bank; relabel, which updates the class vote and stores an exemplar; trim or split at a frame; merge with a neighboring track; or re-prompt, which reruns SAM from a chosen frame over the bad segment instead of opening frame-by-frame editing, since starting annotators from pre-made masklets made them 40% slower in SAM 3's engine ([SAM 3 paper](https://arxiv.org/pdf/2511.16719)).

Missed objects need their own prompt, because reviewing existing boxes cannot find a box that does not exist. Detections below the candidate threshold that no track explains appear as "possible miss" items the reviewer promotes with one click, and a few sampled frames or tiles per video get an exhaustivity question, the per-frame check SAM 3's engine used ([SAM 3 paper](https://arxiv.org/abs/2511.16719)). The Evaluation Inspector's next-error navigation and promote-prediction action, the Uncertain Frames dock, Object Visibility ranges and Edit Object Across Frames already implement most of these interactions ([evaluation_inspector_dock.py:464](../viat/widgets/evaluation_inspector_dock.py#L464), [main.py:1337](../viat/main.py#L1337), [uncertain_frames_dock.py:7](../viat/widgets/uncertain_frames_dock.py#L7), [annotation_dock.py:1787](../viat/widgets/annotation_dock.py#L1787)). Every decision is logged with the track's features, and those logs become the training set for the risk model and the verifier, exactly as SAM 3's verifiers were trained on its Phase-1 human decisions ([SAM 3 paper](https://arxiv.org/html/2511.16719)).

Review time is bounded by the flag rate, not the footage. As arithmetic rather than measurement: at SPAM's observed attention rate of 3.3–20% of objects ([SPAM](https://arxiv.org/html/2404.11426)), 1,000 automatic tracks yield 33–200 queue items, and at an assumed 10 seconds per strip decision (six times the measured 1.6-second box verification ([Papadopoulos et al.](https://ar5iv.labs.arxiv.org/html/1602.08405)), an allowance for scanning a strip that no study has measured) the queue costs 6–33 minutes. The Multidrone result, a workload cut of up to 96% from tracklet verification, is the closest measured analogue ([Ince et al.](https://arxiv.org/abs/2101.06977)).

### A random audit certifies what nobody reviewed

The queue finds errors; it cannot say how many remain in what nobody looked at. That needs a random sample, drawn from the auto-accepted pool, never chosen by the risk model, and reviewed with the same one-key interface. Three audit units need separate numbers: the precision of accepted boxes and tracks, from cheap yes/no decisions; per-frame recall, from expensive exhaustive checks of sampled frames or tiles; and track correctness, from a strip review for ID switches, drift, wrong classes and fragmentation.

Samples must span many videos, because boxes within a frame and frames within a video are correlated, so confidence intervals come from a bootstrap over videos rather than from pretending boxes are independent. Stratifying by risk band and allocating samples by stratum size times error spread (Neyman allocation) shrinks the interval ([stratified PPI](https://arxiv.org/abs/2406.04291)); in our worked example with 400 audited items it cut the standard error from 1.01 to 0.75 percentage points, roughly 1.8 times the effective sample size of simple random sampling.

| Certify accepted-item error at or below | Items to review if 0 errors are found | If 1 error | If 2 errors |
|---|---|---|---|
| 5% | 59 | 93 | 124 |
| 2% | 149 | 236 | 313 |
| 1% | 299 | 473 | 628 |

These are exact one-sided 95% Clopper–Pearson sample sizes ([binomial CI](https://en.wikipedia.org/wiki/Binomial_proportion_confidence_interval)); at the same assumed 10 seconds per decision, a 149-track audit costs about 25 minutes. The stopping rule is sequential: after the queue is worked, draw a fresh random sample from the unreviewed remainder, sign off if the 95% upper bound on its error rate is at or below target, and otherwise send the next tranche of top-ranked tracks to review and repeat, with anytime-valid (betting) bounds if the reviewer peeks mid-sample ([PAC Labeling](https://arxiv.org/html/2506.10908)). The audit size depends on the target and confidence, not on how many tracks the batch contains, so certifying one large overnight batch is far cheaper per label than certifying many small ones.

Targets differ by use. Training data can accept 2–5% certified class and false-positive errors while prioritizing recall, because detectors tolerate missing boxes. Evaluation and test splits need 1% or better, with exhaustively checked frames and guidelines identical to the training set's, because re-annotating COCO with a different guideline actually lowered measured mAP ([Ma et al.](https://openaccess.thecvf.com/content/CVPR2022W/VDU/papers/Ma_The_Effect_of_Improving_Annotation_Quality_on_Object_Detection_Datasets_CVPRW_2022_paper.pdf)). Recall has a hard floor: conformal risk control cannot certify a miss rate below about 1/(n+1), so 100 exhaustively checked frames cannot certify one below about 1% ([CRC](https://arxiv.org/abs/2208.02814)), and for training data recall should be estimated rather than certified.

Once a few hundred audited tracks exist, the risk score can graduate from a ranking to an acceptance rule with a guarantee: conformal labeling selects auto-accepted items by applying Benjamini–Hochberg to p-values computed against audited errors, which controls the false-discovery rate ([Conformal Labeling](https://arxiv.org/html/2510.14581)). Two cautions apply. The calibration set must contain enough errors, because the smallest attainable p-value is 1/(n₀+1) for n₀ audited errors, so at a 5% error rate 400 audited items contain only about 20 errors and calibration must pool across videos. And conservative margins are mandatory: without its confidence-bound margin, threshold-based auto-labeling realized 13.4% error against a 10% target even with 10,000 validation labels ([TBAL](https://arxiv.org/pdf/2211.12620)).

### Logged decisions compound into better rounds

Reviewer decisions feed back through three channels at three speeds. Immediately, rejections become SAM 3 negative exemplars and additions positive exemplars on the frames where errors recur, where three exemplars recover most of the achievable gain ([SAM 3 paper](https://arxiv.org/abs/2511.16719)). Across the dataset, accepted and rejected crops form embedding banks that re-score new detections, with SigLIP 2 (Apache-2.0 and text-alignable) as the embedder ([SigLIP 2](https://arxiv.org/abs/2502.14786)) and 1.0× plus 1.5× crops following ViLD's use of context ([ViLD](https://arxiv.org/pdf/2104.13921)). Between rounds, verified tracks first fine-tune the labeler, since about ten verified instances per class roughly doubled out-of-domain AP for SAM 3 and Grounding DINO ([SAM 3 paper](https://arxiv.org/abs/2511.16719), [RF100-VL](https://arxiv.org/html/2505.20612)), and then train a fast Apache-licensed student such as RF-DETR (62.2 AP50:95 on RF100-VL for the L model, 6.8 ms on a T4) that can re-label long videos quickly ([RF-DETR](https://github.com/roboflow/rf-detr)).

Rounds show diminishing returns: SAM 2's successive data increments added 3.0, 5.8, 3.7 and 0.7 J&F ([SAM 2 paper](https://arxiv.org/html/2408.00714v2)), and semi-supervised detection gains concentrate at 1–50 labels per class ([Practical Insights](https://arxiv.org/html/2601.13380)). Two to four rounds is therefore the realistic budget, stopping when a frozen, video-split hold-out improves by less than about one mAP point, when label churn falls below 1–2%, or when the audited correction rate stays under target for two rounds; these criteria are heuristics, since no study has established stopping rules. Self-training has known failure modes with known guards: keep verified labels in every batch against confirmation bias, down-weight boxes the tracker filled in, and monitor per-class and per-size counts, because small-object pseudo-labels systematically lag ground truth ([Arazo et al.](https://arxiv.org/abs/1908.02983), [RoyChowdhury et al.](https://arxiv.org/abs/1904.07305), [MixPL](https://arxiv.org/html/2312.07006)).

## Conclusion

The fastest route to unattended labeling in VIAT is subtraction before addition. SAM 3 already runs a detector-driven life cycle with births, suppression and re-seeding inside VIAT's process, and VIAT keeps index 0, discards the IDs and scores, and drops the prompt after 400 frames; restoring that information and carrying it through exports into the evaluation engine turns prompt → track into multi-object discovery for scenes with modest object counts and makes every later improvement measurable. For drone footage the evidence also inverts a common intuition: association is the solved half, since box MOT with camera-motion compensation plus offline repair is cheap and well measured, while small-object recall is the unsolved half, so the human minutes automation frees up should be reinvested as exemplars, hard negatives and few-shot data for the detector rather than as tracker tweaks.

"Fully automated" is better defined as unattended generation plus a certified audit than as zero human involvement. The audit is what makes an overnight run trustworthy, its size stays fixed as batches grow, and the decisions it and the queue collect are the only data that can calibrate VIAT's risk score into an acceptance rule. The failure to fear is a silent one rather than a mediocre model (a checkpoint that quietly drops every track, a score that is always 1.0, a dialog waiting at 3 a.m.), which is why health checks, provenance on every box and a random sample the model never chooses belong in the first release, not the last.
